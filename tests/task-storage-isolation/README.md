# Task Storage Isolation: opencode enforcement and adversarial gate

Worker artifacts for the ORCH-4-10 parent (enforce raw task storage isolation) that remain in this repo after the PIRELOC-1 consolidation: ORCH-4-10-3 (opencode enforcement) and the opencode column of ORCH-4-10-4 (the adversarial bypass suite). The pi-column artifacts (the 10-1 feasibility probes and walking skeleton, the 10-2 pi enforcement suite, the end-to-end round-trip gate, and the pi adversarial column) moved with the pi extensions to ThoDHa/pi (PIRELOC-1) and run there. The enforcement surface served here (the tightened agent maps and the `task-storage-guard` plugin) lives under `opencode/.config/opencode/`; everything in this directory runs against fixture repos built per run under `/tmp` or the landed plugin through its real bridge client, never against the live board.

## Contents

- `lib/isolation_common.py` - fixture builders for the adversarial suite: the hermetic git repo with a gitignored `.tasks` tree shaped like a live board, and the sibling worktree carrying its own board. The pi machinery that shared this module's bwrap argv builder moved to ThoDHa/pi with the extensions.
- `lib/oc-task-service.py` - the parent-side broker service: an AF_UNIX server in a 0700 runtime directory that gates every request on a 0600 attribution token, a plugin-registered (session, agent) pair (control requests accepted only from an opencode-binary peer), a 1 MiB request cap and argv width cap, and a per-role `tasks`-verb whitelist byte-aligned with `tests/fixtures/task-access/role-verbs.sh` (worker show/log/report; planner list/show/reports/edit/log/report; reviewer show/reports/list/report; advisor show/reports/list/log/report; scout none; verifier render; the manager never brokers). A sanctioned command must tokenize to a clean `tasks` invocation with no live shell syntax: a quote-aware screen routes compound commands, operators, pipes, redirects, substitutions, tilde/glob/brace expansion, comments, and command-splitting newlines to the masked class, and the sanctioned class re-executes the parsed token list, never the original `bash -c` string. The parsed tokens then pass a per-verb argv policy (flag whitelists, the lexical/kernel-walk/ancestor path policy on every element, bare board-entry taskfile positionals), and write-verb bodies ride the request stdin only: child-named body files are refused outright. Log and report attribution is rewritten server-side to a token-derived `oc-channel-<sha256-16>` label with `TASKS_SESSION` pinned to it; claimed identities survive only in the audit log. Sanctioned verbs execute unmasked on the host with a sanitized env; everything else executes under bwrap with every repository `.tasks` tree (main checkout, worktrees, and every ancestor of the request cwd up to the filesystem root) tmpfs-masked while cwd, `/tmp`, and the main `.git` stay writable. Every request and outcome lands in a JSONL audit log; removing the socket file stops the service.
- `lib/oc-broker-client.py` - the bridge client the guard plugin rewrites each shell call into; carries the original command as a single argv element over the socket (no shell reconstruction at any layer), reads the socket path and token from the runtime directory, captures its own piped stdin as the report/edit body when the command tokenizes to a write-verb invocation (a TTY is never read, and a pipe silent past a one-second priming window yields an empty body), and relays the service response (stdout, stderr, exit) unchanged. Body content fed through shell redirection inside the command string travels as shell syntax and lands in the masked class; the stdin field is the only body channel.
- `test-opencode-enforcement.sh` - the verification suite: map-shape assertions over the six non-manager agent maps (storage denies, bridge-allow ordering, manager access preserved), service unit and gate tests (classify, tokenization, live-shell-syntax screening, peer identity, token/registry/whitelist gates, bwrap mask, size cap, probe pings, opencode-only control channel, audit trail, lifecycle and socket-removal shutdown), the fix-round gates (compound, semicolon, or-list, pipe, substitution, and redirect compositions leak no board bytes and mutate nothing; out-of-board and board-internal body files refused; stdin bodies deposit and read back; spoofed `--from` deposits attribute to the channel label with claimed identities only in the service log; oversized stdin bodies refused by the request cap), and the end-to-end section driving real opencode sessions against fixture repos: storage reads denied (relative and absolute by the maps, symlink through the plugin's realpath guard), sanctioned verbs round-tripping unmasked, direct reads masked with the board invisible, forged client calls refused, version drift degrading fail-closed with a drift marker, rollback behavior (TASKS_BROKER_DISABLE leaves the maps enforcing; plugin and map removal restores direct reads), and board-hash equality proving zero data mutation.
- `run-adversarial.sh` - the adversarial bypass suite and integration gate (ORCH-4-10-4), opencode column: the bypass classes driven through the real BrokerService dispatch path (the bridge client the guard plugin rewrites shell calls into), each with a characterization twin that succeeds without enforcement, plus the routed findings (registered-pair replay, output cap, argv element cap, socket-dir verification) and the transcript-copy-store class. The pi column of this suite runs in ThoDHa/pi against the canonical extensions.

### Running the suites

```
make test-task-storage-opencode
# or directly: bash tests/task-storage-isolation/test-opencode-enforcement.sh [model]
```

The e2e section makes real LLM calls on the fleet worker model (override the model with the first argument) and needs bwrap, opencode on PATH, and a reachable model gateway. On failure the run directory is kept and printed for inspection.

```
make test-task-storage-adversarial
# or directly: bash tests/task-storage-isolation/run-adversarial.sh
```

With `ISOLATION_ALLOW_DEGRADED=1` (the container verify chain's posture) the bwrap-gated machine sections are announced as skipped and the suite gates on what ran. On failure the run directory is kept and its path printed.
