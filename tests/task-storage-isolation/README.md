# Task Storage Isolation: Probes, Skeleton, and Enforcement

Worker artifacts for the ORCH-4-10 parent (enforce raw task storage isolation): ORCH-4-10-1 (feasibility probes and walking skeleton, design-bearing tier), ORCH-4-10-2 (pi enforcement), and ORCH-4-10-3 (opencode enforcement). The 10-1 artifacts below `probes/` plus `run-skeleton.sh`, and the 10-2 pi suite `run-suite.sh`, stay hermetic: the mask, the guard seam, and the escape channel there operate on fixture repos built per run under `/tmp`, never reading the live host extension or the live board. The 10-3 additions (`lib/oc-task-service.py`, `lib/oc-broker-client.py`, `test-opencode-enforcement.sh`) are the live opencode enforcement's parent-side service, bridge client, and verification suite; the enforcement surface they serve (the tightened agent maps and the `task-storage-guard` plugin) lives under `opencode/.config/opencode/`.

## Contents

- `probes/bwrap-probes.md` - deliverable 1 evidence: bwrap unprivileged user-namespace viability, tmpfs masking of a gitignored `.tasks` tree inside a git repo, symlink traversal through the mask, AF_UNIX escape viability, and the net-shared namespace shape. All green.
- `probes/opencode-surface.md` - deliverable 2 evidence: the installed opencode (v2.3.0, superseding the recon's v2.1.4) exposes a `read` permission action and an ordered `permissions` ruleset at schema level; no `sandbox` key exists in the opencode config schema; plugin load paths and the guard hook surface. Includes the embedded Claude-Code-style sandbox runtime finding flagged for the ORCH-4-10-3 mechanism decision.
- `run-skeleton.sh` - deliverable 3: the walking skeleton runner. One run dispatches a pi child through the vendored subagent extension's own spawn path under bwrap with the fixture `.tasks` masked, and demonstrates one denied direct read (plus symlink traversal) and one passed sanctioned `tasks` verb through the parent-side AF_UNIX whitelist service.
- `lib/patch-subagent.py` - runtime copy + patch of the vendored subagent extension. The patch renames `getPiInvocation` and appends a wrapper that prefixes the resolved child invocation with bwrap when `SKELETON_BWRAP_MASK` and `SKELETON_BWRAP_SOCKET` are set. This is the exact seam ORCH-4-10-2 will productionize behind explicit activation; the live extension is never modified, and the patch script fails loudly on upstream seam drift.
- `lib/task-service.py` - the G3-approved escape shape in skeleton form: parent-side AF_UNIX service executing exactly one sanctioned verb shape (`tasks show <fixture-task> --json` against the fixture board), refusing everything else with a logged non-zero response.
- `lib/uds-client.py` - child-side client of the skeleton; sends one argv request over the bind-mounted socket file and relays the service response unchanged.

## ORCH-4-10-2: pi enforcement (production surface + suite)

The pi enforcement slice lands four repo-tracked pieces and this suite:

- `pi/extensions/task-storage-isolation-wrap.py` - the first-class activation mechanism. `activate` inserts a marker-delimited, self-contained TS block at the vendored extension's `getPiInvocation` seam (renamed to `getPiInvocationUnwrapped`); `deactivate` restores the file byte-identically; `verify` reports state by exit status. The patcher refuses (exit 1, file untouched) when the vendored seam shape drifts, and is idempotent once activated. Both `verify` and a re-`activate` pin the installed block's content: the block span is compared against the canonical block, so an in-block edit keeping the markers fails as drift and must be reinstalled with `deactivate` plus `activate` (which still restores the pristine bytes). The inserted wrap prefixes the child invocation with bwrap only while `PI_TASK_STORAGE_ISOLATION` is exactly `1`; when the flag is set but the parent wiring (mask paths, socket, trust file) is absent, empty, or incomplete, the wrap refuses the spawn - it never silently produces an unmasked child. Rollback is flag removal.
- `pi/extensions/task-storage-isolation.ts` - the guard and session wiring extension, inert without the flag. Guard: read/edit/write denials for json-mode child sessions against any `.tasks` tree (lexical, kernel-style component-wise, realpath, and existing-ancestor resolution; the kernel-style candidate is what catches a symlink followed by a dot-dot segment, where the kernel applies `..` to the resolved target and lexical normalization applies it to the name; unresolvable input is denied). The interactive manager session is exempt (the `ctx.mode !== "json"` gate); an explicit unmasked dispatch (`PI_TASK_STORAGE_UNMASKED=1` in the child environment) stands the guard and the wrap down loudly, and recording that dispatch in the task record is the launching manager's audit duty. Wiring: on an activating (non-child) session it enumerates every live `.tasks` tree (session root plus git worktree roots), hosts one per-session `task-storage-isolation-service.py` on a socket under a 0700 scratch dir, generates the session attribution token, and publishes the wiring into the environment the wrap consumes. Drift refusal: before any subagent dispatch it re-verifies the vendored wrap (marker presence plus a sha256 pin of the block content) and refreshes the mask list; a missing marker or an edited block blocks all dispatches until the wrap is reinstalled.
- `pi/extensions/task-storage-isolation-service.py` - the production escape-channel service. Whitelists exactly the sanctioned verb shapes (reads: `show`, `list`, `reports`; writes: `log`, `report` - the two protocol write channels), refuses everything else including `--dir` board redirection, gates on socket-path visibility (bind refuses outside a 0700, user-owned directory) plus a per-session attribution token compared in constant time (SO_PEERCRED is deliberately not used: same-uid children make it a no-op). Path policy: every argv element (positional and flag-attached alike) is normalized with the guard's candidate set (lexical, kernel-style walk, realpath, ancestor) and every candidate must land inside the board repo, the service's one sanctioned surface; taskfile positionals must be bare board-entry names; the report verb accepts bodies from the request stdin only (the `taskfile -` shape or the no-marker shape) and refuses child-named body files outright, so the service never opens a child-named path outside the board and bodies stay bounded by the request cap. Write attribution binds to the service's session registry, which holds exactly one provisioned identity: the token-derived channel label (`iso-channel-<hash>`); log and report requests are rewritten server-side (claimed `--from` dropped, label injected) and run with `TASKS_SESSION` pinned to it, so no child can deposit as another agent, while the claimed values survive in the service log for audit. Requests cap at 1 MiB (draining to a 16 MiB bound so the refusal reaches the client), outputs cap at 16 MiB, each connection's request read is bounded by a 30-second wall-clock window so a hostile slow sender cannot hold the sequential service, and the service exits when its socket is removed or its parent session dies - no daemon surface.
- `pi/extensions/task-storage-isolation-client.py` - the child-side client. Reads socket, token, and session from the child environment (missing pieces are hard errors, never fallbacks), forwards piped stdin as the request body so the write verbs' role-contract shapes work unchanged (a report body on stdin), and relays the service response (stdout, stderr, exit status) so callers use it like the tasks CLI for the sanctioned shapes; file-shaped report bodies and paths outside the board are refused by the service, never silently rewritten.
- `run-suite.sh` - the enforcement suite (92 checks). Gates: py_compile, shellcheck (self), node parse; constant cross-checks pinning the contract names (including the wrap block content digest, derived from the patcher and pinned in the drift checker) across the TS wrap, the python builder mirror, the patcher, and the service; patcher units on a fixture vendored extension (including in-block drift keeping the markers: verify fails, activate refuses untouched, deactivate still restores pristine bytes); node-driven units for the guard's path classes (including the symlink-then-dotdot divergence and its no-over-block control) and the extension factory (drift refusal by marker and by digest, mask refresh, hosted-service round trip, rollback); machine-side bwrap probes executing exactly the suite builder's argv - which a parity check pins byte-for-byte to the installed wrap block, so deny evidence can neither drift from nor be fabricated independently of the production mechanism - plus the masked write round trip driving log and report through the production client; the service units (visibility gate, read/write round trips, F1 refusal pins, service-bound attribution, slow-send window, token/session/verb/`--dir`/oversize refusals, parent-death watchdog).

### Transcript-leak probe (decision-log falsifiable test)

The suite carries the leak pair demanded by the parent's amendment: under the pre-fix trust provision (sessions ro-bound back into the child, `include_agent_dir_sessions` in the builder), a masked child reads a seeded parent transcript carrying board content - the leak demonstrated; under the production shape, `sessions/` (with `auth.json` and `mcp-auth.json`) is never bound, the transcript store is simply absent inside the namespace, and only the scratch trust file appears at `trust.json`. Both directions are asserted, machine-side.

### Design notes: fail-closed posture

Every failure direction lands closed. bwrap absence or failure at spawn time kills the child spawn - the wrap has no unmasked fallback - so kernel changes (`kernel.unprivileged_userns_clone`), AppArmor user-namespace policy, or bubblewrap behavior drift surface as loud spawn failures, never as silent unmasked children. Vendored-file drift (a re-vendored extension wiping the wrap) is caught at dispatch time by the extension's marker check, which blocks all child dispatches until `task-storage-isolation-wrap.py activate` reinstalls the wrap; the patcher itself refuses to patch a drifted seam. Guard paths that cannot be resolved are denied. A service that cannot start, or a session repo with no live `.tasks` tree to mask, blocks dispatches. The suite turns machine drift (bwrap argument semantics, socket-file bind behavior, mask stacking) into red suite results rather than silent enforcement loss; the probe set is machine-scoped (bubblewrap 0.11.1, kernel userns clone enabled, no AppArmor denial, as of 2026-11-17) and the suite re-asserts the behaviors it depends on each run.

### Activation and rollback

Activation is two explicit steps, both operator-owned: run `task-storage-isolation-wrap.py activate` once against the host's vendored extension, then launch the session with `PI_TASK_STORAGE_ISOLATION=1`. Rollback is flag removal: without the flag the wrap returns invocations unchanged, the extension registers no handlers, the service never starts, and no state is written - the suite asserts each of these, including byte-identical restore on `deactivate`.

## Opencode enforcement (ORCH-4-10-3)

- `lib/oc-task-service.py` - the parent-side broker service: an AF_UNIX server in a 0700 runtime directory that gates every request on a 0600 attribution token, a plugin-registered (session, agent) pair (control requests accepted only from an opencode-binary peer), a 1 MiB request cap and argv width cap, and a per-role `tasks`-verb whitelist byte-aligned with `tests/fixtures/task-access/role-verbs.sh` (worker show/log/report; planner list/show/reports/edit/log/report; reviewer show/reports/list/report; advisor show/reports/list/log/report; scout none; verifier render; the manager never brokers). A sanctioned command must tokenize to a clean `tasks` invocation with no live shell syntax: a quote-aware screen routes compound commands, operators, pipes, redirects, substitutions, tilde/glob/brace expansion, comments, and command-splitting newlines to the masked class, and the sanctioned class re-executes the parsed token list, never the original `bash -c` string. The parsed tokens then pass a per-verb argv policy (flag whitelists, the lexical/kernel-walk/ancestor path policy on every element, bare board-entry taskfile positionals), and write-verb bodies ride the request stdin only: child-named body files are refused outright. Log and report attribution is rewritten server-side to a token-derived `oc-channel-<sha256-16>` label with `TASKS_SESSION` pinned to it; claimed identities survive only in the audit log. Sanctioned verbs execute unmasked on the host with a sanitized env; everything else executes under bwrap with every repository `.tasks` tree (main checkout, worktrees, and every ancestor of the request cwd up to the filesystem root) tmpfs-masked while cwd, `/tmp`, and the main `.git` stay writable. Every request and outcome lands in a JSONL audit log; removing the socket file stops the service.
- `lib/oc-broker-client.py` - the bridge client the guard plugin rewrites each shell call into; carries the original command as a single argv element over the socket (no shell reconstruction at any layer), reads the socket path and token from the runtime directory, captures its own piped stdin as the report/edit body when the command tokenizes to a write-verb invocation (a TTY is never read, and a pipe silent past a one-second priming window yields an empty body), and relays the service response (stdout, stderr, exit) unchanged. Body content fed through shell redirection inside the command string travels as shell syntax and lands in the masked class; the stdin field is the only body channel.
- `test-opencode-enforcement.sh` - the verification suite: map-shape assertions over the six non-manager agent maps (storage denies, bridge-allow ordering, manager access preserved), service unit and gate tests (classify, tokenization, live-shell-syntax screening, peer identity, token/registry/whitelist gates, bwrap mask, size cap, probe pings, opencode-only control channel, audit trail, lifecycle and socket-removal shutdown), the fix-round gates (compound, semicolon, or-list, pipe, substitution, and redirect compositions leak no board bytes and mutate nothing; out-of-board and board-internal body files refused; stdin bodies deposit and read back; spoofed `--from` deposits attribute to the channel label with claimed identities only in the service log; oversized stdin bodies refused by the request cap), and the end-to-end section driving real opencode sessions against fixture repos: storage reads denied (relative and absolute by the maps, symlink through the plugin's realpath guard), sanctioned verbs round-tripping unmasked, direct reads masked with the board invisible, forged client calls refused, version drift degrading fail-closed with a drift marker, rollback behavior (TASKS_BROKER_DISABLE leaves the maps enforcing; plugin and map removal restores direct reads), and board-hash equality proving zero data mutation.

### Running the suite

```
make test-task-storage-opencode
# or directly: bash tests/task-storage-isolation/test-opencode-enforcement.sh [model]
```

The e2e section makes real LLM calls on the fleet worker model (override the model with the first argument) and needs bwrap, opencode on PATH, and a reachable model gateway. On failure the run directory is kept and printed for inspection.

## End-to-end round trips (ORCH-4-10-4)

`run-e2e-roundtrip.sh` is the integration gate: one full manager dispatch round trip per harness with enforcement on, driven through the real spawn paths (the machine-side suites never make a model call; this script does - two per harness, manager parent and worker child). The pi leg activates the child-wrap on a fixture agent dir (the patcher's own activate path against a full copy of the host agent dir minus the never-bound entries), launches the manager session with `PI_TASK_STORAGE_ISOLATION=1`, and dispatches a real worker through the vendored subagent extension under bwrap; the oc leg runs a primary manager agent in a fixture carrying the landed plugin and maps and has it dispatch a worker subagent whose shell commands are brokered. Each child session completes sanctioned board writes (a Work Log checkpoint plus, on pi, a report deposit) that land on the host board under channel attribution (`iso-channel-`/`oc-channel-`, claimed identities rewritten server-side) while every direct-access probe in the same session is denied: relative, absolute, symlink, and dot-dot masked reads, the compound composition, and the structured read-tool lane (pi guard denial, oc plugin realpath-guard denial with worker attribution).

```
bash tests/task-storage-isolation/run-e2e-roundtrip.sh [model] [pi|oc|both]
```

The masked pi child authenticates from the environment: the wrap never binds `auth.json` (or `sessions/`) into the namespace, so the run needs `ZAI_API_KEY` (ambient wins; otherwise the script reads the provider key from the host auth store into the run env at run time and the store itself never crosses the boundary). The run directory is kept and printed on failure.

## Running the skeleton

```
bash tests/task-storage-isolation/run-skeleton.sh
```

Requires: bwrap, pi, the tasks CLI on PATH, the vendored subagent extension at `~/.pi/agent/extensions/subagent`, and a reachable model gateway (the run makes two LLM calls: parent dispatcher and worker child, both on the fleet worker model by default; override with `run-skeleton.sh <model>`).

Success output is the acceptance evidence:

```
SKELETON-VERDICT: DENY-VERIFIED (direct and symlink reads denied under mask)
SKELETON-VERDICT: PASS-VERIFIED (sanctioned tasks verb round-tripped through the UDS service)
```

On failure the runner keeps its scratch directory and prints its path for inspection.

## What the skeleton establishes

The bash-boundary mechanism contract the per-harness enforcement slices (ORCH-4-10-2, ORCH-4-10-3) build on:

1. The vendored extension's child spawn (`getPiInvocation` resolution feeding `spawn` with json-mode argv, inherited env, ignore/pipe/pipe stdio) functions unchanged under a bwrap prefix that ro-binds the host, tmpfs-masks the fixture `.tasks`, and shares the network namespace (model-bound children need the gateway).
2. The mask denies every read class probed (direct, relative, absolute, parent-traversal symlink, realpath-normalized) with no lexical path guard involved.
3. Sanctioned board verbs pass through a parent-side whitelist service over a bind-mounted socket file while the child keeps no other view of the masked tree.
